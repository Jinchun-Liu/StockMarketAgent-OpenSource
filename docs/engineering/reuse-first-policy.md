# 成熟开源复用优先规范

<!-- governance-doc:reuse-first-policy:v1 -->

本规范约束所有人类开发者、Codex、Claude Code 及其他代码 Agent。目标是把“先复用成熟实现、
没有合适实现才自行设计”变成可审查、可追溯、可持续维护的工程流程，而不是一句口号。

## 1. 强制原则

新增能力、依赖、基础设施、模型、算法、数据连接器或大段实现前，必须先完成复用调研。结论只能是：

- `adopt`：直接依赖成熟项目，通过现有 Port 使用；
- `adapt`：复用稳定能力，但以本项目 adapter 隔离厂商或框架类型；
- `reference`：只借鉴公开设计，不复制代码，不形成运行时依赖；
- `reject`：因维护、安全、架构或质量原因不采用；R7 起也包括许可与数据权利不合格；
- `build`：已有候选均未通过硬门槛，记录缺口后自行实现最小必要领域能力。

不得同时保留多套没有真实需求的平行实现。调研可以比较多个候选，但最终必须给出一个默认路线；
其他候选写明拒绝理由与重新评估触发条件。

## 2. 何时必须建立复用决策记录

以下变更必须在 `docs/research/reuse-decisions/` 新建或更新记录、同步
`governance/reuse-decisions.json`，并在任务四字段或最终报告中链接：

- 新产品能力、跨模块工作流或非平凡算法；
- 新增、替换或大版本升级第三方包、服务、镜像、模型或数据 SDK；
- fork、复制、移植或实质改写第三方代码、提示词、规则、schema、前端组件；
- 自研已有常见实现的缓存、队列、解析、OCR、检索、去重、通知、图表、训练、评测或回测能力；
- 许可证、维护状态、数据权利或供应链风险发生变化。

局部缺陷修复、纯文案修改或使用已批准能力的普通业务代码可以在任务说明中填写
“不产生新复用决定”，但必须说明理由。不得把大功能拆成多个小提交来规避记录。

## 3. 必须执行的调研步骤

1. 写清问题、输入输出、规模、延迟、准确性、隐私、可观测性和验收标准，不先指定喜欢的框架。
2. 先查本仓库已有 contract、Port、任务、事件、`governance/interfaces.json`、
   `governance/metrics.json`、`docs/research/open-source-evaluation.md`、`THIRD_PARTY.md` 和既有决策记录；
   仓库内已有语义对应项必须优先复用或兼容演进，避免内部重复后再谈外部引入。
3. 查询候选项目的官方仓库、官方文档、发布页、许可证、SECURITY、测试和维护状态；不得用聚合文章、
   星标数或模型记忆替代一手核验。
4. 有两个及以上可信候选时至少比较两个；只有一个时记录检索范围及其他候选为何不可信或不相关。
5. 分开记录代码许可、模型权重许可、训练数据许可、外部数据/接口条款、字体/图标/示例资源许可；
   R1–R6 的个人研究预览允许把尚未完成正式核验的外部数据标为 `DEV_ONLY/UNVERIFIED` 后试用，R7
   起必须完成用途、缓存、embedding、训练与再分发逐项核验。
6. 先做隔离原型、contract test 和代表性基准，再决定引入；未经验证的 README 功能声明不能写成已满足。
7. 记录最终版本、tag/commit、制品 SHA-256、容器 digest、许可证、NOTICE、修改内容、CVE 和退出方案。
8. 只有候选全部未过硬门槛时才能选择 `build`，并把确切缺口和最小自研边界写入记录。

网络事实可能变化。实际引入或升级时必须重新核验，而不能把历史调研日期当成永久批准。

## 4. 硬门槛

出现以下任一情况默认 `reject`；其中许可和数据权利条款从 R7 起是硬门槛。R1–R6 若项目所有者明确
指定个人研究预览来源，可作为 `DEV_ONLY/UNVERIFIED` 例外并记录退出条件：

- 没有清晰许可证，许可证路径混合但无法逐文件界定，或来源无法唯一确认；
- 许可证禁止计划中的商业使用，或 source-available/Commons Clause/专有部分会锁定产品；
- GPL/AGPL/SSPL 等强义务与预期分发或网络服务方式尚未完成专项审查；
- 项目已归档、停止维护，或安全敏感运行时没有可接受的修复与迁移渠道；
- R7 数据端点、抓取、缓存、全文、embedding、训练或再分发权利不清楚；
- 需要接入真实下单、规避登录/验证码/限流/robots/条款，或默认向第三方发送私有数据；
- 破坏 point-in-time、evidence、修订链、权限失败关闭、幂等或本仓库依赖方向；
- 必须把厂商 SDK、ORM、框架对象或裸字典泄漏到公共 Port/contract；
- 缺少可固定版本、可重放输入、离线测试或合理降级路径，且无法通过 adapter 补救。

MIT、Apache-2.0、BSD、PostgreSQL License 等宽松许可证优先，但仍需检查 NOTICE、商标、专利、
附带模型/数据和传递依赖。GPL/AGPL 并不等于“禁止商用”，但在本项目中属于需要专项批准的条件采用，
不能被自动标记为可直接融合。source-available 不能标记为开源。

## 5. 统一评分与决定

通过硬门槛后按 100 分记录：

| 维度 | 权重 | 核验内容 |
|---|---:|---|
| 能力匹配 | 40 | 必要功能、数据市场、性能、扩展点、降级 |
| 工程成熟度 | 20 | 发布、维护者、测试、文档、兼容与安全响应 |
| 许可与商业可用性 | 15 | 代码/模型/资源许可、NOTICE、商标、传递义务 |
| 数据权利与安全 | 15 | 来源授权、隐私、网络行为、供应链、默认配置 |
| 集成与运维 | 10 | Port 隔离、资源成本、备份恢复、观测、退出成本 |

分数用于比较通过硬门槛的候选，不得用高分覆盖硬门槛失败。星标、fork 数和宣传性 benchmark 只能作为
辅助信号。最终记录必须包含证据和判断，不允许只填总分。

## 6. 复用的工程边界

- 第三方能力由 `src/stock_assistant/platform` adapter 实现 `src/stock_assistant/ports` 中的 Port；
  领域模块不得 import 第三方 SDK。
- 第三方响应先校验并转换为本项目 Pydantic contract；不得穿越模块、任务、事件或 HTTP 边界。
- 版本、网络、时间、随机数和模型输出必须可固定；测试使用 fake/脱敏 fixture，不访问真实服务。
- 所有 I/O 显式超时；重试有界且只用于可重试错误；副作用带幂等键；失败按权利和安全要求关闭。
- fork 是最后手段。只有能力覆盖显著高、许可清晰、长期维护成本低于 adapter 集成时才允许；
  fork 必须有上游同步策略、差异清单、SECURITY 更新来源和退出方案。
- 复制代码必须保存来源仓库、精确 commit、原文件路径、许可证头、修改说明和必要 NOTICE。
- 新依赖必须进入锁文件、SBOM、漏洞/许可证扫描和 `THIRD_PARTY.md`；镜像固定 digest，模型固定 revision/hash。

## 7. 允许自行实现的范围

本项目应自行拥有与产品不变量直接相关、且通用项目无法可靠提供的最小领域层，例如：

- 数据权利 gate、许可快照和来源失败关闭；
- A 股证券/公司/行业/地区的 point-in-time 映射；
- evidence、事实槽位、事件 revision、冲突与实质变化判定；
- 通知幂等、盘前简报差异和板块公平轮换规则；
- 历史可见性约束、金融困难集、融合质量闸门和 paper-only 安全边界。

即使选择 `build`，其中的通用子问题仍要复用成熟库。例如自研事件变化规则不等于自研 PDF 解析、
OCR、向量索引、MinHash、模糊匹配、任务队列、通知协议、训练器或可观测性系统。

## 8. 交付与复审

实现、测试、文档和决策记录必须在同一改动中同步。任务说明与最终报告合计至少写明：

- 决策记录链接和最终 `adopt/adapt/reference/reject/build`；
- 评估过的候选、官方证据、许可证和数据权利；
- 固定版本/commit/hash、adapter 边界、基准与 contract test；
- 自研时的未满足缺口；
- 退出、替换、回滚和重新评估触发条件。

每次大版本升级、许可证变化、归档/维护者变化、重大 CVE、数据条款变化或连续无法满足 SLO 时重新评估。
当前全项目候选目录见 `docs/research/open-source-evaluation.md`，直接使用登记见 `THIRD_PARTY.md`。

`scripts/check_governance.py` 会失败关闭地校验登记文件、可信候选数量、唯一决定、默认路线、自研缺口、
记录 marker 和 `THIRD_PARTY.md` 同步项。机器检查不能判断法律结论或证据质量；这些仍由
PAE 产品与架构标准部、DMI 数据与市场情报部和 QIR 质量、运行与集成部在最终审查及里程碑集成
中人工复核，禁止把“格式通过”表述成“许可证/数据权利已批准”。部门不授予写权限，实际单写角色
仍以任务明确范围、固定单写区和真实 Git diff 为准。
