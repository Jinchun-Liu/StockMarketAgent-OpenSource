版本：2026-09-09
状态：R1合成链路已验证；R2私人真实研究入口已部署，原五项及两项真实验收均失败、无报告，采集修复尚待发布。精确版本、实现证据、已使用样本和续作阻碍见当前任务 (upstream private record, excluded)；生产就绪状态只以 `governance/delivery.json.production_release_gates` 为准。

## 当前R2真实资料要求

- 真实路径从空事实包与真实接口结果开始：Tavily发现 → 受控网页/PDF原文 → Flash提取 → Pro独立资料审核 → 按缺口补抓 → Pro研究/评分/联合核验 → 保存报告。不得用默认事实、模型记忆或合成财务/事件补位。
- 搜索摘要仅作线索；事实必须绑定原文位置、规范证券、数字/单位/期间及可核实发布日期。搜索缺日期允许先受控抓原文，版权年份、报告期间、抓取/HTTP修改时间不能当发布日期；冲突和历史截点越界拒绝。
- 公司身份及主营审核通过后才处理其他维度。每项最多三次额外尝试，查询/原文去重，传输重试不另算补抓；取消、权限、截止时间和跨worker配额优先。身份或主营失败不生成公司分析，其余缺项保留部分报告。
- 审核通过不改变来源身份/授权或独立来源数量；接口也检查证券、字段、单位、期间，明显异常隔离。扫描PDF或不可可靠提取的表格记缺口，不猜数字。
- 六维分档、权重与程序复算保留；缺维不评分、总分为空，不重新分配权重。Bull/Bear、综合判断及报告事实支持仍需核验；事实与合理推断明确区分。
- JSONB checkpoint保留候选、审核裁决、单项尝试次数、查询/原文记录和已通过事实；恢复匹配公司、输入、截点与规则版本。未审核候选不能发布。页面、下载、打印共享保存内容及来源/审核/缺口。
- 保留24小时登录、七日会话历史、取消、部分结果和恢复；活动研究上限5与单项额外补抓上限3是不同限制。现有七个真实样本授权已使用完，失败记录保留，不擅自重跑或扩样。
- 仅私人研究，保持DEV_ONLY/UNVERIFIED；不绕过来源权限、robots、登录、验证码、限流或访问控制。当前不是生产、商业授权或真实报告质量验收通过。


## 1. 产品定位

StockMarketAgent 是面向单用户的 A 股信息研究助手；支持隔离本地开发，当前运行环境为私人云端预览。当前用户选择并确认一只 A 股后，系统创建
独立、有限生命周期的研究会话，而不是激活长期关注。它解决的不是“自动赚钱”，而是三件可验证的事：

1. 在明确 PIT 截点下整理与指定标的相关的历史事实，并说明来源、时效、变化和覆盖缺口；
2. 把公告、政策、研报、新闻和聚合舆情变成统一事件，避免旧闻和转载反复推送；
3. 把历史预测、当时证据与事后结果留档，以严格样本外方法验证量价与文本融合是否真的有增益。

外部市场、国际政策、制裁、地缘事件、商品、汇率、利率和供应链冲击属于事件与基本面轴。系统只在
存在可审计公司暴露时生成条件化影响推断；它们不进入交易结构压力分数，也不构成涨跌概率。

在这三项基础上，产品增加一个独立的“交易结构压力”能力：用确定性、可拆解的量价和市场结构代理
帮助用户理解当前拥挤与回撤脆弱性。它是状态压缩，不是下跌概率、目标价或买卖建议。

系统长期保持研究工具属性：不开放注册、不收费、不做广告、不公开荐股、不承诺收益、不连接券商真实下单。

## 2. 用户与边界

唯一用户是项目所有者。系统只支持一个逻辑账户，但表结构保留 `owner_id`，便于隔离测试数据。R2
允许按代码、简称或全称搜索 A 股；歧义结果必须由用户确认。确认后创建 `ResearchSession`，不修改
`active_target`、不创建 watchlist、不接收持仓，也不启动未来监测。

### 统一术语

- `research_session` / 研究会话：围绕一个已确认规范证券的一次性深度研究，默认保留七天。
- `active_target` / 主动关注标的：R1 固定目标兼容对象，R2 运行时不绑定。
- `portfolio_position` / 可选持仓：用户可不填写的数量、成本等私密仓位信息，不决定是否激活。
- `reference_instrument` / 参照证券：只参与宽基、行业、同行或外部环境数值基线，不处理公司新闻或通知。

文档、契约和任务幂等不得用 `portfolio` 或 `watchlist` 代指研究会话。

### R1 合成来源、五类覆盖、变化与证据边界（冻结）

- R1 出口只使用仓库内原创固定 fixture；任何真实供应商、网页或账户都不得参与该候选运行。
- 五类 fixture 使用独立 `source_id`、游标、成功水位和故障状态，并显著标记“合成测试数据”。
- R1 五类覆盖固定为：法定公告、财务变化、行情快照、公司与行业新闻、相关宏观快讯。五个区块始终
  存在并分别返回覆盖状态；“没有新增事实”与“来源失败/缺权”必须是不同状态。
- 五类能力不互相补位。任一接口失败只降级对应类别，不能把另一类别、回放数据或旧水位写成成功；
  页面必须显示真实的最后成功时间。来源切换必须新建稳定 `source_id`，不得改写历史证据身份。
- 用户可见的实质变化恰好四种：`NEW` 表示首次出现的稳定逻辑事件；`UPDATE` 表示同一事件的状态或
  实质字段更新；`CORRECTION` 表示来源明确更正、撤回或替换先前事实；`CONTRADICTION` 表示同一事实
  槽位与期间存在无法同时成立且仍有效的两个 evidence claim/revision，二者可以拥有相同或不同
  `source_id`。同一来源发布两个未声明替换关系的冲突 claim 仍是 `CONTRADICTION`；只有来源明确标记
  replacement/retraction 的方向性修订才是 `CORRECTION`。重复转载和字节级重放不属于第五种变化。
- 每个事实必须引用 `evidence_id`；证据保留来源记录 ID、官方 URL、checksum、rights snapshot、
  `published_at`、`first_seen_at`、`fetched_at` 与 `revision_known_at`。稳定逻辑事件 ID 不变，
  实质变化只追加不可变 revision，不能覆盖旧证据。
- 历史查询以 `decision_time/as_of` 过滤 knowledge time：任何
  `first_seen_at > decision_time` 或 `revision_known_at > decision_time` 的记录均不可见。来源 cursor
  是 adapter 拥有的不透明值，只在整批证据、对象和 revision 原子成功后推进；任一失败保持最后成功
  cursor。两个来源的游标、水位、错误和重试不得合并为一个“总体成功”。
- 同一事实的多源证据合并到同一稳定事件并保留全部 `evidence_id`；同槽同期间的不同有效值生成
  `CONTRADICTION`，不得平均、覆盖或用来源排序静默消解。
- 正式来源适配器保留权利预检和失败关闭，不允许未授权真实网络调用。生产发布前必须逐项完成来源授权、
  shadow trial、live E2E 与模型资格；此前只能展示为合成/非生产数据。
- “已证实事实”“系统推断”“概率研究”是三个独立信息区。事实只陈述证据；推断必须列依据和
  不确定性；概率必须带模型、`as_of` 和 `paper_only=true`。任一区域缺失都不能由另一区域补写。

- 沪、深、北 A 股证券主数据与历史时点行业/地区映射；
- R1 固定目标兼容读取；不面向用户提供主动关注或自选写入；
- 公司概况、主营、财务报表、法定公告；
- 与用户股票解耦的全球国际官方事件库，以及创建研究会话时的零跳/一跳证据化传导；
- 国内外政策、国际组织/央行决定、制裁、出口管制和地缘事件的 PIT revision、冲突与更正；

- 本地模型服务、两阶段 LoRA 和可回滚模型登记；
- 量价、文本事件和概率融合的研究及纸面运行。

### 明确不做

- 真实交易、自动下单、仓位优化或券商账户托管；
- 绕过验证码、风控、robots、私有签名或 API 配额；
- 在四项生产发布门禁通过前保存、训练或展示任何真实供应商新闻、研报和股吧全文；
- 用股吧帖子确认公司事实；
- 用回测期之后的大模型知识生成历史特征；
- 把“方向准确率”或 LoRA 幻觉下降比例写成先验承诺。
- 把交易结构压力 0–100 分解释为概率、预计跌幅、主力行为或交易信号；
- 从日线/10 分钟行情推断具体交易者身份，或在缺失核心股本/规则/同行数据时强行评分。
- 前期同时深度处理多只股票、全市场逐股新闻、全板块公平轮换或全市场压力快照物化；
- 未来持续跟踪、定时关注、用户通知或多股票工作区；
- 两跳以上供应链推断、把新闻共现当作供应关系，或用海外市场变化机械预测 A 股方向。

## 3. R2 用户主流程

1. 用户输入六位代码、带交易所代码、简称或全称；系统返回规范候选、匹配类型、上市状态和 PIT 截点。
2. 用户明确确认证券；系统以幂等键创建独立 `ResearchSession` 和异步 job。
3. 页面只展示真实阶段、最后进展时间和覆盖缺口，不展示半成品报告或虚假百分比。
4. worker 构建 PIT 公司数据包，读取截至 `as_of` 可见的全球事件 revision，以确定性规则匹配最多一跳的
   公司/行业暴露并区分“无相关事件”和“事件库不可用”。
5. 模型拆解问题并生成多视角、Bull/Bear、未知项与可证伪叙事；不得创造暴露边或补全事件库缺口。
6. 确定性验证器检查身份、时间、事实单位与数值、引用、来源独立性、事件路径和禁用投资建议；模型分析再经过事实摘录精确匹配与现有语义支持核对。正文可保留有依据的数值和时期，但不得补造事实或无依据预测。剔除不受支持的候选后，只有最终看多、看空与综合判断均完整且合格才一次性发布报告；缺少核心分析时仍按有效证据执行六维评分并编排七段易读版、十个专业区块，保留可用结果并标为部分完成，剔除情况同时披露。评分和已核验叙事进入既有 checkpoint，恢复时按输入和版本复用，取消或预算到期后停止模型调用。
7. 报告默认七天到期；用户可取消、重试、查看历史或提前删除，后台在二十四小时内清除正文、影响匹配与短期制品。

接口、状态机和错误语义见
[`r2-multi-source-memory.md`](../roadmap/workstreams/r2-multi-source-memory.md)。

## 4. 核心功能验收描述

### 4.1 指定股票研究与证券主数据

- R1 只加载固定标的 `XSHG:603986`（`603986.SH`，兆易创新），首次建立 revision 1，重复加载
  幂等；任何其他证券在外部访问前返回 `R1_TARGET_LOCKED`。
- R2 搜索接受 `600519.SH`、`000001.SZ`、`430047.BJ`、六位代码、简称和全称，并确定性归一化为
  `XSHG/XSHE/XBSE` 身份；模糊或重名必须由用户确认。
- 每个代码解析到历史时点有效的证券、公司、行业、注册地、总部和主要经营地。
- 证券更名、行业调整、迁址、上市和退市均保留 `valid_from/valid_to`，回测不读取今天的映射。
- R2 不接收持仓数量或成本价；每个研究会话恰好绑定一个证券，多个会话不共享临时上下文。
- `Watchlist` 契约及冻结的 `PortfolioRepositoryPort 1.1` 已定义主动标的 revision 的读写语义；
  repository adapter 仅用于 R1 兼容；R2 不调用其写能力。

### 4.2 盘前简报

- 默认比较“上次成功简报之后”而不是任意自然日。
- 法定公告和正式政策永远入库，不因情绪分低而丢弃；只有与主动标的无关时才不进入简报。
- 每条内容标注 `NEW / UPDATE / CORRECTION / CONTRADICTION`，重复转载计数但不重复展示。
- 展示已证实事实、系统推断、概率预测三个独立区域；任何事实均可跳转到原始来源。
- 数据源失效时显示缺口、最后成功时间与延迟，不用模型填补空白。
- 任一研究来源发生凭据缺失、接口权限不足、403、429、timeout 或结构变化时，其覆盖独立降级；
  只显示稳定原因、最后成功时间、业务 watermark、批次审计 ID 和“未推进”状态，不向 UI、HTTP
  或无障碍树暴露原始 provider cursor，也不向另一来源或第三方静默 fallback。
- 法定公告、财务变化、行情快照、公司与行业新闻、相关宏观快讯五个区块始终存在并独立表达
  `covered/no_change/degraded/rights_blocked` 等稳定状态。
- LLM 离线时仍由确定性流程展示四种变化、事实证据、revision 和来源健康；系统推断与概率区可以明确
  不可用，但不能隐藏已确认事实。
- 外部环境对象即使数据不足也必须存在并标记 `INSUFFICIENT`；海外休市和未定价事件分别显示，不能
  用旧值构造零变化。

### 4.3 政策追踪

- 以国务院政策文件库和允许列表内的地方政府官网为源。
- 根据公司的行业、注册地、总部、生产基地和项目地计算相关性。
- 原始政策事实和“可能影响哪些公司/行业”的模型推断分别保存。
- 政策提到行业不等于个股利好；缺少适用对象、资金规模、生效时间等关键字段时标记“影响待确认”。
- 国际政策、央行、制裁和出口管制遵循同样的事实/推断分离；战争、物流中断等事实属于市场事件，目标
  影响必须经官方点名、公司披露、一跳证据或行业背景四级路径表达。

### 4.4 盘中板块轮动（后续扩展）

前期只观察主动标的及其行业数值参照，不处理全市场逐股新闻或公平轮换。多股票和全板块能力保留为
长期扩展；恢复该范围前必须重新评估用户价值、数据权利、计算成本和提醒负担，不能沿用旧计划直接启用。

### 4.5 数据与记忆分层

- Valkey 只保存短任务锁、relay 状态和限流；不保存长期个股语义记忆。
- 会话正文、影响匹配、模型上下文和 embedding 绑定 `session_id + expires_at`，最长七天；提前删除立即不可访问。
- 全球事件事实、raw evidence、revision、rights snapshot 和最小审计按 PIT/权利政策保留，但不是模型语义记忆。
- `macro_reference_facts` 是唯一长期语义记忆，只接受稳定定义、制度关系、分类和已确认历史事实；当前事件、
  个股暴露、方向推断、预测和模型结论写入必须失败。
- `EpisodicMemoryPort` 不绑定 R2；R2 不生成用户通知。

### 4.6 证据对话（R3后续规划）

- 仅围绕当前会话已保存证据询问公司变化、财务、政策和数据缺口；不接收或分析持仓。此项不是当前R2已验收能力。
- 工作流固定为意图识别、权限判断、检索、证据打包、结构化生成、确定性校验、流式展示。
- 模型不能直接访问数据库或网页，只能调用受限工具并读取证据包。
- 无证据、证据冲突、信息过期或请求超出权限时明确拒绝下结论。

### 4.7 本地模型与外部模型

- 当前获准私人真实研究使用 `deepseek-v4-flash` 规划/提取，以及独立 `deepseek-v4-pro` 资料审核、研究、评分和报告核验；取数与报告分开调用，仅使用既有托管凭据引用。
- Qwen3.5-9B/vLLM与LoRA属于后续R5路线；历史“外部模型仅聊天”不适用于本轮已批准研究调用，其他用途不自动继承授权。
- 外发前删除账户号、持仓数量、成本价和个人笔记；历史回测和自动预测禁止调用外部模型。
- 所有生成记录 provider、精确模型版本、adapter、prompt hash、规则版本、证据 ID、token、耗时和原始响应哈希。

### 4.8 预测研究

- 第一版只研究“09:20 形成信号、09:30–09:35 VWAP 假设成交、预测收盘相对行业基准的超额收益概率与区间”。
- 价格模型与文本影响模型分别产生严格样本外预测，再由校准后的融合模型组合。
- 未通过回测和 60 个交易日纸面运行前，UI 中 `ENABLE_DIRECTIONAL_FORECAST=false`。

### 4.9 交易结构压力

统一 R4 已重定界为“用户发起研究时计算一次 PIT 市场结构快照”。它不读取 `active_target/watchlist`，
不持续运行十分钟监控、不生成盘中档位变化、09:40 反馈、通知或 SSE。详细规格见
[`r4-behavior-pressure.md`](../roadmap/workstreams/r4-behavior-pressure.md)。

## 5. 非功能要求

### 时效目标

当前R2以用户发起的单次研究、阶段心跳、端到端截止时间和诚实部分结果为准；尚未证明真实链路时延目标。下表是旧持续采集/后续模型路线的规划参考，不启用盘中监测、主动标的摘要或通知；具体统一指标只在 `governance/metrics.json` 定义。

| 数据 | 目标 | 说明 |
|---|---:|---|
| 法定公告 | 首次可用后 60 秒 | 依赖研究接口及上游可用性 |
| 公司与行业资讯 | 60 秒 | 依赖接口能力和账户配额 |
| 券商研报 | 10 分钟 | 不保证全文缓存权 |
| 中央政策 | 15 分钟 | 条件请求、保守限流 |
| 地方政策 | 30–60 分钟 | 各站点单独授权登记 |
| 主动标的摘要 | 每 10 分钟 | 只更新单标的与相关行业数值参照；板块轮动延期 |
| 盘中压力临时值 | 完整 10 分钟窗口后 120 秒内 | 只物化当前主动标的；参照总体批量复用，数据不完整则降级或 abstain |
| 盘后压力确认值 | 数据水位完整后 | 不以固定时钟掩盖供应商延迟 |
| 普通聊天首 token | 本地 3 秒内 | 24GB GPU 基线，短证据包 |

这些是服务目标，不是对第三方数据可用性的保证。每次展示同时给出实际延迟。

### 可靠性与恢复

- 同一任务可安全重试，入库、聚类、推送和 outcome 回填均幂等。
- 连接器 1、5、30 分钟退避；连续第三次失败自动熔断并告警。
- PostgreSQL 每日逻辑备份、每周恢复演练；SeaweedFS 开启版本保留，Valkey 可重建。
- API 或模型不可用不影响证据入库；模型恢复后从 outbox 补处理。

### 可观测性

- 结构化日志包含 request/job/cluster/model/run ID，不包含密钥、持仓明细和授权全文。
- 候选观测问题至少覆盖源延迟、429/403、队列深度、去重率、更新率、推送抑制率、引用校验失败、
  模型耗时和 GPU 使用率；这里不定义正式指标，首个真实生产者出现时以
  `governance/metrics.json` 的 metric ID、公式、单位和标签为准。
- 所有预测可追溯到数据 manifest、代码提交、模型版本、规则版本和特征截止时间。
- 所有交易结构 assessment 可追溯到公式、特征、同行、交易规则、数据 manifest、rights snapshot 和
  `MarketDataLineageRef`；证券代码不作为 Prometheus 标签。

## 6. 当前必须确认的外部输入

工程路线已经唯一确定，但以下事实无法从代码推断：

1. 最终训练/部署机器的系统、GPU 与显存、内存、可用磁盘；当前暂按 Linux + NVIDIA CUDA、24GB 显存、64GB 内存、500GB 空间编排。
2. 正式发布前确认拟采用的数据服务及合同是否允许行情/内容的获取、保留、派生、展示和 LLM 输入，
   并完成 shadow trial 与真实供应商 E2E；这不阻断合成开发，但阻断任何生产就绪声明。
3. GitHub 远程仓库公开或私有；持仓与密钥安全考虑下默认按私有处理。

这些输入不会改变领域架构。R1/R2 候选只使用原创确定性合成数据；正式来源必须补齐逐用途 rights
snapshot、影子运行、live E2E 与模型运行资格后才能移除“非生产数据”标识。
