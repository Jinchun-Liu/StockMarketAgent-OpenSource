# R5：本地模型与 LoRA 实施规格

> 路线编号由原 R4 顺延为 R5；能力边界不因编号变化而提前。

状态：规格 `approved`；交付 `blocked`，待统一 R4 会话快照、证据基线、金标和硬件闸门。
机器状态与阻塞码以 `governance/delivery.json` 中的 `R5` 为准。

## 用户结果

模型只能基于证据生成结构化输出，证据不足时拒答，故障时退回证据列表；只有基础模型存在稳定且可训练的错误模式时才进行 LoRA。交易结构压力的公式、分数、驱动和缺失判断不依赖 LLM。

## 前置闸门

- R4 的压力指数即使存在，也只作为版本化结构化上下文，不作为 LoRA 训练捷径或事实来源；
- 至少 500 个完全人工审核、许可可用、按实体簇和时间隔离的金标；
- 固定 base model、tokenizer、prompt、rule、runtime revision/hash；
- 目标硬件 spike 验证模型格式、结构化输出、LoRA 加载、吞吐、内存和连续运行；
- 外部 provider 只接收经过隐私过滤的证据，不含持仓数量、成本或个人笔记。

## TDD 与评估顺序

1. 先测试 JSON Schema、引用存在、数字一致、主体一致、拒答和 prompt injection；
2. 实现本地/外部 provider 的统一现有端口及确定性降级；
3. 跑未微调基线并分类错误，不直接训练；
4. 仅对稳定错误构建阶段 1 指令数据，运行多 seed LoRA；
5. 阶段 1 通过后，加入财报、回购、减持、政策、行业和舆情权重标注做阶段 2；
6. 与基线、规则和前一 champion 做盲测、消融、回归和回滚演练。

## 采用约束

训练高层运行器保持单一；候选、许可、固定版本和退出方案登记到复用注册表及 `THIRD_PARTY.md`。
vLLM-Metal 和 MPS 训练只是 macOS 候选，不等同于 NVIDIA 支持；未通过 spike 就保持未支持状态。

## 退出条件

JSON Schema 合法率 ≥99.5%，引用存在率 100%，数字一致率 ≥99%，应拒答召回率 ≥95%；LoRA 不得使
任一安全或引用指标退化。每次生成可按模型、adapter、prompt、rule、evidence 和 hash 回放。

R5 的合规退出不以“必须训练 LoRA”为条件。若固定基础模型已经通过上述质量、安全和回放闸门，且基于
人工金标的错误分析没有发现稳定、可训练且值得 LoRA 修复的问题，可以记录“无需启动 LoRA”的结论并
完成 R5；该结论必须保留基线结果、错误分类、金标版本、模型/prompt/rule/runtime manifest 和复审证据。
不得为了宣称完成阶段而制造训练任务。只有确认存在稳定可训练错误时，两阶段 LoRA 才成为退出前的必做
路径。

## 降级与回滚

模型不可用、OOM 或校验失败时返回确定性证据列表并标记原因；adapter 通过静态版本切换回上一
champion，不在线热切不明版本；受影响输出可按版本定位并撤回。

## 接口、指标与标准同步

优先复用现有模型 provider/evaluation Port，不为不同推理引擎创建同义接口。真实 provider、adapter 和
contract test 同时存在后才提升接口状态；真实评测生产者落地时才登记 schema、引用、数字、拒答、
延迟/OOM 等指标。每次 base/adapter/prompt/rule 变更同步模型 manifest、复用决策、`THIRD_PARTY.md`、
锁文件、回滚说明和测试。
